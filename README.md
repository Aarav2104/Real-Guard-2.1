# Real Guard / Reel Guard

A research prototype: an Instagram-inspired app whose metadata (including third-party ad-form data) passes through a **jurisdiction-aware, deterministic privacy guard** before reaching a simulated recommender. A **Data Privacy Analysis** area shows what happened to every field.

## Run
```bash
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp ../.env.example .env                                  # optional; add OPENROUTER_API_KEY to enable the LLM policy-structuring step
python -m uvicorn app.main:app --reload                            # open http://localhost:8000
python -m pytest -q                                      # 28 tests
```
The FastAPI server also serves `frontend/`, so there is nothing else to start. SQLite lives in `backend/data/` (git-ignored).

## Pipeline (what each module does)
| Stage | Module | Notes |
|---|---|---|
| Metadata collection | `main.py` `/api/events`, `/api/events/batch` | likes, saves, follows, shares, searches, watch time, profile, ad-form fields |
| Jurisdiction detection | `jurisdiction.py` | platform region override → timezone → language region → `UNKNOWN`. Extend the tables to add countries. |
| Policy discovery | `sources.py`, `discovery.py` | fetches only URLs in the registry; stores text, SHA-256, timestamp, status; failures are recorded, never fatal |
| LLM structuring | `structuring.py` + `llm.py` | OpenAI-compatible provider layer (default OpenRouter free models). Output is an **untrusted candidate**; a missing key is an explicit error, never a fake success |
| Validation | `validator.py` | schema, actions/methods, params, `ref` citation required, conflicts, ALLOW on direct/sensitive data rejected, purposes |
| Repository | `repository.py` | versioned policies; only valid ones can be activated (explicit `/activate`); rollback = re-activate |
| Real Guard | `classifier.py`, `guard.py`, `transforms.py` | deterministic; no matching rule → BLOCK; transform failure → BLOCK; no active policy → strict fallback |
| Recommender | `recommender.py` | API path builds its profile from **protected values only** |
| Metrics | `metrics.py` | computed from stored events |
| UI | `frontend/` | Instagram-style dark web UI (spec in `frontend/DESIGN.md`): icon rail, stories, feed, Reels with a distinct sponsored reel, Messages, Search/Explore, Notifications panel, Profile, Create, Data Privacy Analysis |

Seeded **reference policies** (India DPDP Act 2023, EU GDPR, California CCPA/CPRA) are hand-authored, illustrative rules, labelled "offline reference snapshot". They are a starting point, not legal interpretations; the discover → structure → validate → activate flow is how newer rules would replace them.

## LLM provider (optional step)
The LLM is used **only** for "Structure with LLM" in Data Privacy Analysis → Policy. Real Guard decisions never call it, so the whole app works with no key (decisions then come from the seeded `reference` policies; there is no mock LLM mode).

1. Create a free key at https://openrouter.ai/settings/keys.
2. `cp .env.example backend/.env`, then set `OPENROUTER_API_KEY=` (never commit `.env`; it is git-ignored). Restart the server.
3. `OPENROUTER_MODEL=openrouter/free` lets OpenRouter pick any currently free model. Pin one instead with a model id ending in `:free` (see https://openrouter.ai/models?pricing=free), and optionally set `OPENROUTER_FALLBACK_MODELS`.
4. Another provider: set `LLM_PROVIDER=openai_compatible` plus `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. All provider code is in `backend/app/llm.py`.

Free-tier notes: free models are rate limited (HTTP 429 → the app retries once, then shows a clear message), models rotate without notice, and OpenRouter caps free requests per day depending on whether you have bought credits. Free-model JSON quality varies, which is why every candidate must pass the validator and be activated by you.

## Metadata types generated by normal use
| Interaction | Field(s) | Default class | Typical policy outcome |
|---|---|---|---|
| Like, save, share, repost, follow, story view | `like` `save` `share` `repost` `follow` `story_view` | recommendation signal | ALLOW |
| Reel / ad watch time | `watch_time` | behavioral | TRANSFORM → 5 or 10 s bucket |
| Search, hashtag tap | `search` `hashtag` | behavioral | TRANSFORM → topic category |
| Open someone's profile | `profile_visit` | behavioral | TRANSFORM → pseudonym |
| Comment, new-post caption | `comment` `caption` | sensitive (free text) | TRANSFORM → topic category only |
| Direct message text | `dm` | sensitive | BLOCK |
| Profile / Edit profile | `name` `email` `phone` `account_id` `age` `city` | identifiers / quasi / location | pseudonym · redact · age range · region |
| Device, precise location | `device` `geo` | quasi / location | TRANSFORM → OS family · rounded coordinates |
| Sponsored-reel application form | `name` `email` `phone` `age` `city` `skills` `education` `job_interest` `resume` | mixed | resume BLOCK, skills ALLOW, others per policy |

Rows are reference-policy defaults for India; EU/California differ (see the Policy tab). No matching rule always means BLOCK.

## Metrics
- **Risk** = Σ category weight × residual factor. Weights: direct 10, sensitive 9, quasi/location 5, behavioral 2, recommendation 1. Residual: allow 1, pseudonym 0.4, range/region/bucket/category 0.3, redact/block 0.
- **Privacy risk reduction %** = (baseline − protected) / baseline × 100.
- **Utility retained %** = baseline-scored value of the top-5 recommendations chosen from the *protected* profile ÷ that of the top-5 chosen from the *raw* profile × 100.
- Latency avg/p95 per guard decision. `GET /api/selftest` checks transformation correctness (e.g. age 21 → 20–25, watch 18 s → 15–20 s).

Weights/factors are author-chosen assumptions; results describe this synthetic session and are not a general accuracy claim.

## API (selected)
`POST /api/session` · `POST /api/session/{id}/region` (re-applies policy to all records) · `POST /api/events` · `POST /api/events/batch` · `GET /api/events|metrics|recommendations|ads?session_id=` · `GET /api/policies` · `POST /api/policies/{code}/discover|structure` · `POST /api/policies/{id}/activate` · `POST /api/policies/validate` · `GET /api/selftest`. Interactive docs at `/docs`.

## Limitations
Prototype only: no Instagram integration; simulated recommender; discovery may fail or return partial pages (PDF sources are not parsed); LLM output may be wrong, so it is validated and needs human activation; registry URLs must be verified by a human; jurisdiction detection from timezone/language is approximate (e.g. VPNs, travellers); generalisation and pseudonymisation do not guarantee anonymity; pseudonym tokens use HMAC with a server key; raw originals are stored (synthetic data only) so the analysis view can show before/after; no legal-compliance guarantee. Use synthetic data only; never commit `.env`.

## Not done yet / future work
